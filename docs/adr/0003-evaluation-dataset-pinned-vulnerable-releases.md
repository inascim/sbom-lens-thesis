# Evaluation dataset: regenerated, pinned to older releases, filtered to vulnerable SBOMs of at most 1k components

The original evaluation results were lost, so Chapter 7's data is regenerated from scratch by a deterministic pipeline, not by an LLM agent choosing projects. The pipeline takes a committed project list, clones each project at an older release tag (about 2–3 years old), generates a CycloneDX SBOM with cdxgen, runs SBOM Lens's analyses, and dumps the metrics. The ecosystems are npm, PyPI and Maven, about 30 projects each. The sample is deliberately biased: an SBOM is kept only if it has **at least one known vulnerability** (the thesis needs to measure vulnerability reach) and **at most 1,000 components** (a scope limit). Both filters are reported as threats to validity. SBOMs, raw metric dumps and the vulnerability-query date go in version control pushed to GitHub, with a Zenodo snapshot at submission, so that the results no longer depend on one disk. Vulnerabilities come from exactly the sources the tool uses (NVD, OSV and GHSA), through the same code: the pipeline runs `../sbom-lens/src/utils/vulnerabilityAPI.js` under Node and posts the results to the backend, so Chapter 7 evaluates the code the tool actually runs. This means an NVD API key and a GitHub token are required for collection. The pipeline, project list and data live in a separate `sbom-lens-eval` repository, which pins the `sbom-lens` commit it evaluated. Collection runs only after the dominance fix (ADR 0002) and the per-severity overlay are in the code.

## Considered Options

- Current HEAD, filtered to vulnerable SBOMs: rejected, because many current projects come back clean and most of the collected SBOMs would be thrown away.
- A mixed vulnerable/clean sample: rejected as unnecessary for the RQs.
- Reimplementing the lookup in Python, or dropping NVD for the evaluation: rejected, because the evaluated sources and code must match the tool.
- syft as the generator: rejected, because its CycloneDX output often leaves `dependencies[]` sparse or empty, which would produce edgeless graphs.
